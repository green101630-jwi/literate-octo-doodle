01 / TEMPORAL CONTEXT

When does observation history help?관측 이력은 어떤 작업에 도움이 되는가?

Why & approach문제와 접근

A single frame can be ambiguous about task phase and object motion. I extended ACT with sampled observation history and future-state auxiliary supervision, then compared the complete ACT and TC-ACT configurations on two bimanual tasks.단일 프레임만으로는 작업 단계와 물체의 움직임을 구분하기 어려울 수 있습니다. ACT에 관측 이력과 미래 상태 보조 학습을 연결하고, 두 양팔 작업에서 ACT와 TC-ACT의 전체 구성을 비교했습니다.

What this taught me실험에서 얻은 질문

The benefit was task-dependent: the temporal configuration improved handover while reducing basket success. This motivates identifying which task phases need history, rather than assuming more history always helps. The comparison changes the complete model configuration; it does not isolate the causal effect of history alone.시간적 문맥 구성은 handover에서 개선됐지만 basket에서는 낮아졌습니다. 이 결과는 이력을 늘리는 것 자체보다 어떤 작업 단계에서 이력이 필요한지를 분석하게 했습니다. 전체 모델 구성이 달라진 비교이므로 관측 이력 하나의 인과 효과로 해석하지 않습니다.

02 / DIFFUSION POLICY DEPLOYMENT

A faster model still needs a correct execution loop.빠른 모델에도 정확한 실행 루프가 필요합니다.

Why & approach문제와 접근

I connected a low-dimensional Diffusion Policy to ROS 2 hardware, checked the observation / normalization / joint-order contract, and profiled inference against a 50 Hz action target. The Task2 path uses 14D joints + 6D environment state, two observations, 16 predicted actions, eight executed actions, and DDIM10.저차원 Diffusion Policy를 ROS 2 하드웨어에 연결하고 관측·정규화·관절 순서를 확인한 뒤, 50Hz 행동 발행에 맞춰 추론 지연을 측정했습니다. Task2 조건은 관절 14D+환경 6D, 관측 2개, 16개 행동 예측·8개 실행, DDIM10입니다.

The C128 model reduced U-Net channels and was retrained. Runtime work combined compilation with a full-sampler CUDA Graph and persistent input buffers. A worker handles inference separately; late responses keep the previous target, and actions are consumed once in order.U-Net 채널 수를 줄인 C128 모델을 재학습하고, 컴파일·전체 sampler CUDA Graph·입력 버퍼 재사용을 결합했습니다. 추론은 별도 worker에서 처리하며, 응답이 늦으면 직전 목표를 유지하고 행동을 한 번씩 순서대로 소비합니다.

Observation freshness is separate관측의 신선도는 별도 문제

A read-only live-feedback probe reduced source-message age from about 192–195 ms to 3–6 ms by changing the subscription depth from 20 to 1. This improved observation freshness, not GPU inference speed.명령을 보내지 않은 실시간 피드백 시험에서 구독 큐 depth를 20→1로 바꾸자 원본 메시지 나이가 약 192–195→3–6ms로 줄었습니다. 이는 GPU 가속과 별개인 관측 지연 개선입니다. [2]

Interpretation & next question해석과 다음 질문

Model size, inference latency, sensor age, transport delay, and action order need separate measurements. The 796-action result verifies sequence delivery, not task success. My next question is how to optimize execution while preserving the timing assumptions under which a policy was trained.모델 크기·추론 지연·센서 나이·통신 지연·행동 순서를 구분해 측정해야 합니다. 796개 행동 기록은 순서 전달 검증이며 작업 성공률이 아닙니다. 학습 시 정책이 전제한 시간 관계를 유지하면서 실행을 개선하는 방법이 다음 질문입니다.

From demonstration coverage to timed action chunks.시연 데이터의 범위에서 행동 청크의 실행 시점까지

I compared data sources and trainable modules, then examined how its longer inference time interacts with continuous physical execution.SmolVLA는 RGB와 언어 지시를 조건으로 행동을 생성합니다. 데이터 출처와 갱신하는 모듈을 달리해 학습하고, 긴 추론 시간이 연속적인 실물 실행과 어떻게 맞물리는지 확인했습니다.

Hardware evidence & limits실물 기록과 해석 범위

Physical runs and a yellow-cube grasp-and-transfer segment are preserved. The comparison also contains failed initial grasp attempts. Operator intervention and unjudged outcomes prevent a matched hardware success-rate claim for the four models.실물 구동과 노랑 큐브를 집어 상자로 옮긴 구간이 보존되어 있으며, 첫 집기 실패 기록도 있습니다. 손 개입과 미판정 시행이 있어 네 모델의 동일 조건 실물 성공률을 주장하지 않습니다. [6]

Synchronous baseline and asynchronous implementation동기 기준선과 비동기 실행 구조

In a synchronous baseline, execution waits for a new prediction. In the implemented asynchronous path, one worker predicts chunk B while the control loop executes chunk A. The returned chunk is aligned to the request observation time; already elapsed rows are skipped, and overlapping actions can be blended.동기 기준선은 새 예측이 끝날 때까지 실행이 기다립니다. 구현한 비동기 경로는 worker가 청크 B를 계산하는 동안 제어 루프가 청크 A를 실행합니다. 응답은 요청 시 관측 시각에 정렬하고 이미 지난 행을 건너뛰며, 겹치는 시점의 행동은 혼합할 수 있습니다.

This is an execution design comparison, not a completed controlled experiment showing that asynchronous inference improves success. The action clock uses a software timestamp around the request, not the camera exposure time.실행 구조의 비교이며 비동기 추론이 성공률을 높인다는 통제 실험 결과는 아닙니다. 행동 시계는 카메라 노출 시각이 아닌 요청 부근의 소프트웨어 시각을 사용합니다.

What remains open남아 있는 연구 질문

A longer action horizon is not necessarily fully used: inference delay removes a prefix, while a new chunk can replace the previous tail. I want to measure action age and actual chunk contributions alongside task outcomes, then choose chunk length and replanning cadence under controlled timing.추론 지연으로 앞부분을 쓰지 못하고 새 응답이 이전 청크의 뒷부분을 대체하므로, 긴 행동 청크가 전부 활용되는 것은 아닙니다. 행동 나이와 실제 청크 기여를 작업 결과와 함께 측정하고, 지연 조건에 맞는 청크 길이·재계획 간격을 찾고자 합니다.

Q1 / TEMPORAL INFORMATION

Which phase needs history?어떤 단계에 이력이 필요한가?

Vary history length, history sampling and auxiliary supervision separately on matched demonstrations. Analyze approach, grasp, transfer and release phases rather than only final averages.같은 시연에서 이력 길이·샘플링·보조 학습을 각각 바꾸고, 최종 평균과 함께 접근·집기·전달·놓기 단계를 분석합니다.

Q2 / EXECUTION TIMING

Which actions are still useful?어떤 행동이 아직 유효한가?

Compare synchronous and asynchronous execution with the same checkpoint, reset states and delay traces. Sweep chunk length and query cadence; measure action age, used rows and transition discontinuities.체크포인트·초기 상태·지연 기록을 고정해 동기·비동기 실행을 비교합니다. 청크 길이·질의 간격에 따른 행동 나이·활용 행·전환 불연속을 측정합니다.

Q3 / DATA & TRANSFER

What survives a change of domain?환경이 달라도 유지되는 것은 무엇인가?

Hold the evaluation environment and training budget fixed while varying demonstration coverage and trainable modules. Include the deployment adapter in simulator evaluation before comparing physical execution.평가 환경·학습 예산을 고정한 채 시연 범위와 갱신 모듈을 바꿉니다. 실물 비교 전 배포 adapter를 반영한 시뮬레이션 평가를 수행합니다.

Evaluation commitment평가 원칙

Report task success and completion time together with latency, observation / action age, and failure mode. Use declared reset states, multiple training seeds where feasible, fixed success criteria, and separate records for operator intervention. A shorter runtime or a higher chunk-use ratio will not by itself count as improved manipulation.작업 성공·완료 시간과 지연·관측 및 행동 나이·실패 유형을 함께 보고합니다. 초기 상태·성공 기준을 명시하고 가능한 범위에서 학습 시드를 반복하며 손 개입을 별도 기록합니다. 실행 시간 단축이나 청크 활용률 증가만으로 조작 성능이 개선됐다고 판단하지 않습니다.
